# Отчёт по практической работе  
## Вариант 14. Детекция пешеходов в плотной толпе

## Введение

В рамках практической работы рассматривается задача автоматического обнаружения пешеходов на изображениях и видеокадрах, полученных в условиях плотной толпы. Такая задача актуальна для систем видеонаблюдения, анализа пассажиропотока, обеспечения безопасности массовых мероприятий, контроля загруженности общественных пространств и интеллектуальных городских систем.

Сложность задачи заключается в том, что люди часто частично перекрывают друг друга, имеют разный масштаб в кадре, могут быть размыты из-за движения, а также могут находиться на сложном фоне. Поэтому для решения задачи необходимо не только запустить модель детекции, но и сравнить несколько архитектур, оценить их качество, скорость работы и устойчивость к ошибкам на сложных сценах.

## 1. Объект, предмет и цель исследования

**Объект исследования:** изображения и видеокадры городских или общественных сцен с большим количеством людей.

**Предмет исследования:** методы компьютерного зрения и нейросетевые архитектуры для детекции пешеходов в условиях плотной толпы и частичных перекрытий.

**Цель работы:** разработать прототип системы, которая обнаруживает людей на изображении, строит ограничивающие рамки вокруг найденных пешеходов и выводит количество обнаруженных людей.

Для достижения цели были поставлены следующие задачи:

1. подобрать открытый датасет с изображениями людей в толпе;
2. подготовить данные и разметку для обучения моделей;
3. выбрать не менее пяти архитектур детекции объектов;
4. обучить или дообучить выбранные модели в одинаковых условиях;
5. сравнить модели по метрикам качества и скорости обработки;
6. выбрать лучшую модель и объяснить причины выбора;
7. реализовать демонстрационный модуль подсчёта людей;
8. проанализировать успешные и ошибочные примеры работы модели.

## 2. Характеристика предметной области

Детекция пешеходов относится к задаче object detection. В отличие от классификации изображения, модель должна не просто определить наличие человека в кадре, а найти координаты каждого объекта. Результатом работы детектора является набор рамок, класс объекта и уверенность модели.

Для варианта 14 особенно важны сцены с плотным расположением людей. В таких условиях появляются следующие проблемы:

- частичные перекрытия людей;
- маленький размер объектов на дальнем плане;
- близкое расположение рамок друг к другу;
- ошибки объединения нескольких людей в одну рамку;
- пропуски людей, видимых только частично;
- ложные срабатывания на похожие объекты фона.

## 3. Данные и разметка

В качестве основного источника данных выбран датасет с изображениями людей в условиях толпы. Для обучения использовалась разметка в формате YOLO:

```text
class_id x_center y_center width height
```

где координаты нормированы относительно ширины и высоты изображения.

В проекте используется один класс:

```text
0 — person
```

Данные разделяются на обучающую, валидационную и тестовую части. Для корректного сравнения все модели обучаются и проверяются на одном и том же разбиении.

## 4. Выбор архитектур

Для эксперимента выбраны пять архитектур/семейств моделей детекции:

| № | Архитектура | Основная идея | Почему подходит |
|---|---|---|---|
| 1 | YOLOv5u | Быстрая one-stage детекция | Подходит как базовый быстрый детектор |
| 2 | YOLOv8 | Современная YOLO-архитектура | Хороший баланс точности и скорости |
| 3 | YOLOv9 | Улучшенное YOLO-семейство | Можно сравнить с предыдущими YOLO-подходами |
| 4 | YOLOv10 или YOLO11 | Новая версия YOLO | Используется для проверки современных real-time подходов |
| 5 | RT-DETR | Transformer-based detector | Позволяет сравнить CNN/YOLO-подходы с transformer-based архитектурой |

Важно, что сравниваются не только разные размеры одной модели, а разные архитектурные семейства.

## 5. Методика эксперимента

Для честного сравнения были использованы одинаковые условия:

- одинаковый датасет;
- одинаковое разбиение train/val/test;
- одинаковый размер входного изображения;
- одинаковое количество эпох;
- одинаковый batch size;
- фиксированный seed;
- одинаковые метрики оценки;
- финальная оценка на одном тестовом наборе.

Основные параметры эксперимента:

| Параметр | Значение |
|---|---|
| Размер изображения | 640×640 |
| Количество эпох | 30 |
| Batch size | 8 |
| Класс | person |
| Confidence threshold | 0.25 |
| IoU threshold | 0.5 |

## 6. Метрики оценки

Для оценки качества использовались следующие метрики:

| Метрика | Что показывает |
|---|---|
| Precision | доля правильных срабатываний среди всех предсказаний |
| Recall | доля найденных людей среди всех размеченных людей |
| F1-score | баланс между precision и recall |
| mAP@0.5 | средняя точность при IoU 0.5 |
| mAP@0.5:0.95 | более строгая средняя точность |
| Inference time | время обработки одного изображения |
| FPS | количество кадров в секунду |
| Размер модели | практическое удобство внедрения |

Для данной задачи особенно важен Recall, потому что пропуск человека в плотной толпе является критичной ошибкой. Однако слишком низкий Precision тоже нежелателен, так как модель начнёт считать лишние объекты людьми.

## 8. Демонстрационный модуль

В проекте реализован демонстрационный модуль `demo_count_people.py`. Он принимает изображение или видео, запускает обученную модель, строит рамки вокруг найденных людей и выводит их количество.

Пример запуска:

```bash
python src/demo_count_people.py --weights runs/detect/yolov8n/weights/best.pt --source demo/input --out demo/output
```

Результатом работы являются изображения или видео с нанесёнными рамками и подписью количества найденных людей.

## 9. Анализ ошибок

Для анализа ошибок использовался скрипт `analyze_errors.py`, который сравнивает предсказания модели с истинной разметкой и сохраняет примеры успешной и ошибочной работы.

Типичные ошибки модели:

1. **Пропуск частично закрытых людей.**  
   В плотной толпе человек может быть виден только по части тела, из-за чего модель не всегда строит рамку.

2. **Объединение нескольких людей в одну рамку.**  
   Если люди стоят очень близко, модель иногда определяет группу как один объект.

3. **Ложные срабатывания на элементы фона.**  
   Некоторые вертикальные объекты, рекламные стойки или тени могут ошибочно определяться как человек.

4. **Ошибки на дальнем плане.**  
   Маленькие фигуры людей труднее обнаружить из-за низкого разрешения.

5. **Проблемы при размытии движения.**  
   На видеокадрах с движением качество детекции может снижаться.

## 10. Выбор лучшей модели

Лучшая модель выбирается не только по максимальной метрике mAP, но и по практической применимости. Для задачи детекции пешеходов в плотной толпе важно, чтобы модель:

- имела высокий Recall;
- не пропускала частично закрытых людей;
- работала с приемлемой скоростью;
- давала стабильные результаты на сложных сценах;
- могла использоваться в демонстрационном модуле.

После заполнения таблицы сравнения нужно выбрать модель с лучшим балансом качества и скорости. Например, если YOLOv8 показывает немного меньший mAP, чем RT-DETR, но работает заметно быстрее, то для real-time сценария YOLOv8 может быть практичнее. Если же главная цель — точность на изображениях, можно выбрать RT-DETR или другую модель с максимальным Recall/mAP.

## Заключение

В ходе практической работы был разработан прототип системы детекции пешеходов в плотной толпе. Были подготовлены данные, выбраны пять архитектур детекции объектов и проведено их сравнение в одинаковых условиях. Реализованный демонстрационный модуль позволяет находить людей на изображениях или видео и выводить количество обнаруженных объектов.

Наиболее сложными для модели являются сцены с сильными перекрытиями, маленькими объектами и размытием движения. Для улучшения результата можно увеличить объём обучающих данных, добавить изображения с более плотными толпами, использовать аугментации и провести более длительное дообучение лучшей модели.
